1. Introducción teórica

¿Qué es Git?

Git es un programa que guarda todas las versiones de un proyecto. Si algo sale mal, se puede volver a una versión anterior. También permite que varias personas trabajen en el mismo proyecto sin borrar el trabajo de las demás. GitHub es la página web donde se guarda el proyecto en internet.

¿Qué es Git Flow?

Git Flow es una forma de ordenar el trabajo con Git. Usa ramas con nombres fijos, y cada una sirve para algo distinto:

  • main: guarda las versiones finales.
  • develop: es donde se juntan las cosas nuevas mientras se trabaja.
  • feature/...: una rama para cada cosa nueva. Sale de develop y vuelve a develop.
  • release/...: sirve para preparar una versión nueva antes de pasarla a main.
  • hotfix/...: sirve para arreglar algo rápido de la versión final. Sale de main.

¿Por qué lo usamos en este proyecto?

  • Somos 3 personas y cada una hace una parte distinta. Con una rama para cada parte, nadie pisa el trabajo de los demás.
  • El trabajo queda ordenado: se sabe qué se hizo y quién lo hizo.
  • La versión final (main) siempre está limpia, porque lo nuevo se prueba antes en develop.
  • El cliente ve que trabajamos con un método serio.

Para simular a tres personas, antes de trabajar como cada usuario cambio mi nombre en Git con git config user.name y git config user.email. Además, escribo el nombre del usuario al final de cada mensaje de commit, por ejemplo [Usuario2].

2. Proceso paso a paso

2.1 Usuario 1: crea el repositorio y la estructura inicial

Entro en GitHub y creo un repositorio nuevo que se llama curso-javascript-html. Lo dejo público y con README.

Con git clone me bajo el repositorio a mi ordenador. Después entro en la carpeta con cd.

Le digo a Git que ahora soy Usuario1, con su nombre y su correo. Con el último comando compruebo que el nombre está bien.

Preparo Git Flow con git flow init. Dejo los nombres que propone por defecto y solo escribo v como prefijo de las versiones. Así se crea la rama develop.

Subo las dos ramas principales, main y develop, a GitHub con git push.

Copio la plantilla HTML5 Boilerplate en mi carpeta y escribo index.html: la cabecera con el nombre del curso, el menú con el enlace a Home, una descripción del curso y el pie de página.

Creo el archivo curso.css con los estilos de la cabecera (con imagen de fondo), del menú y del pie de página.

Con git add . preparo los archivos, con git commit los guardo con un mensaje que lleva [Usuario1] y con git push origin develop los subo a la rama develop de GitHub. Los avisos de LF will be replaced by CRLF no son errores, son avisos de Windows.

2.2 Usuario 2: crea dos features

Feature 1: contingutHTML (Modificar contenido HTML)

Cambio mi nombre en Git a Usuario2 y compruebo que se ha cambiado.

Con git flow feature start contingutHTML creo la rama feature/contingutHTML a partir de develop. Git me pasa a esa rama.

Creo la página contenido-html.html, con ejemplos de JavaScript que cambian el contenido de la página con innerHTML y la explicación de cada código.

Añado en el menú de index.html el enlace a "Modificar contenido HTML".

git add . y git commit guardan los cambios (con [Usuario2] en el mensaje). git flow feature publish sube la rama a GitHub. git flow feature finish -k une la feature con develop (con -k la rama no se borra). Por último, git push origin develop sube develop a GitHub.

Feature 2: atributsHTML (Modificar atributos HTML)

Con git flow feature start atributsHTML creo la rama feature/atributsHTML a partir de develop, que ya tiene la primera feature.

Creo la página atributos-html.html, con ejemplos de JavaScript que cambian atributos de HTML (setAttribute, getAttribute y removeAttribute) y su explicación.

Añado en el menú de index.html el enlace a "Modificar atributos HTML".

Hago los mismos pasos que en la feature anterior: add, commit con [Usuario2], feature publish, feature finish -k y push de develop.

2.3 Usuario 3: crea una feature y la release v1.0

Cambio mi nombre en Git a Usuario3 y creo la rama feature/estilsCSS con git flow feature start estilsCSS.

Creo la página estilos-css.html, con ejemplos de JavaScript que cambian los estilos de un elemento con element.style. El código lleva comentarios que explican cada línea.

Añado en el menú de index.html el enlace a "Modificar estilos CSS".

Guardo los cambios con commit (con [Usuario3]), subo la rama con feature publish, la uno a develop con feature finish -k y subo develop con push.

La release v1.0

Ahora develop ya tiene las tres features. Creo la release con estos comandos:

git flow release start 1.0
git flow release finish -m "Release v1.0" 1.0

Al terminar la release, Git abre el editor nano para escribir el mensaje de la unión con main. Añado [Usuario3] y guardo con Ctrl+O, Enter y Ctrl+X.

El editor se abre otra vez, ahora para unir el tag v1.0 con develop. Añado [Usuario3] y guardo igual.

Miro el historial dibujado con git log --graph --oneline --all --decorate. Se ven las tres features, el commit del Usuario 1, la unión de la release en main y el tag v1.0.

Subo main, develop y los tags a GitHub con git push origin main develop --tags. Sale [new tag] v1.0.

Compruebo en GitHub que el tag ya está subido: aparece "1 tag".

En GitHub creo la release a partir del tag v1.0, con un título y unas notas que dicen lo que incluye la versión.

2.4 Usuario 1: hace un hotfix

Vuelvo a ser Usuario1 y creo el hotfix con git flow hotfix start milloresV_1_0. La rama hotfix/milloresV_1_0 sale de main.

Mejoro contenido-html.html: añado un botón para vaciar la lista, un tercer ejemplo que compara innerHTML con textContent, una tabla resumen y un aviso de seguridad.

Al terminar el hotfix se abre nano para el mensaje de la unión con main. Añado [Usuario1] y guardo.

Se abre otra vez, para unir el tag del hotfix con develop. Añado [Usuario1] y guardo. Git Flow pone la v delante de los tags solo, y yo también la escribí, por eso el tag se llama vv1.0.1.

Miro otra vez el historial. Ahora se ve el commit del hotfix, su unión con main y con develop, y el tag nuevo.

Con git tag veo los tags (v1.0 y vv1.0.1). Con git branch -a veo todas las ramas: main, develop, las tres feature/... y hotfix/milloresV_1_0.

Subo todo a GitHub con git push origin main develop --tags.

3. Proyecto de GitHub y colaborador

  • Añado al usuario antoni-gimenez como colaborador del repositorio (Settings → Collaborators).
  • Creo un proyecto con un tablero en la pestaña Projects y lo uno al repositorio. También le doy acceso a antoni-gimenez.
  • En el tablero hay una tarjeta por cada feature y por el hotfix: feature/contingutHTML, feature/atributsHTML, feature/estilsCSS y hotfix/milloresV_1_0. Cada tarjeta tiene su descripción, su etiqueta, la persona que la hizo, la rama y el commit. Todas están en la columna Done.
